## 一、ROS是什么类型的软件？能干什么？

### 1.1 软件类型：元操作系统（Meta-Operating System）

ROS（Robot Operating System）**不是**一个传统意义上的操作系统（如Windows或Linux），它无法独立启动电脑。
它**运行在Linux之上**，是一套为机器人开发设计的**分布式通信框架**和**工具集**。

ROS 2本质上是一个基于**匿名发布/订阅机制**的中间件（Middleware），允许不同进程之间传递消息。它像一个“软件总线”，
让机器人的不同部件（摄像头、激光雷达、电机控制、计算大脑）能以标准化的方式相互对话。

### 1.2 它能干什么？

- **硬件抽象**：屏蔽不同传感器（如不同品牌的激光雷达）的底层驱动差异，让算法代码“一次编写，到处运行”
- **分布式计算**：支持将计算任务分配到多台计算机上（例如：摄像头图像处理在显卡强劲的电脑A上跑，运动控制在嵌入式板卡B上跑）
- **代码复用**：全球开发者将导航、视觉、机械臂控制等算法封装成“功能包”（Package），你可以像搭积木一样直接拿来用
- **仿真与调试**：配合Gazebo仿真环境，在无实体机器人时即可开发；并提供`rqt`、`rviz2`等图形化工具进行可视化调试

## 二、ROS 2 核心术语

这是理解文档和源码的基础，以下术语结合你刚跑通的`diff_drive_robot`项目来理解：

### 2.1 节点（Node）

**节点**是ROS 2图中参与通信的基本单元，它使用客户端库与其他节点通信。从本质上说，一个节点就是一个可执行文件（C++或Python）。

ROS 2将复杂的系统分解成许多模块化的节点，每个节点应该只做一件逻辑上的事情。

- **你项目中的例子**：`teleop_twist_keyboard`（键盘控制节点）、`gz sim`（Gazebo仿真节点）

### 2.2 话题（Topic）

**话题**是节点间**异步**、**单向**的数据传输通道，采用**发布/订阅**模式。节点可以向命名话题**发布**（publish）数据，
也可以**订阅**（subscribe）命名话题来接收数据。

话题是ROS 2通信中的重要元素，充当节点交换信息的“总线”。

- **你项目中的例子**：`/cmd_vel`（速度指令话题）。键盘节点**发布**速度，小车节点**订阅**速度

### 2.3 消息（Message）

**消息**是话题上传输的数据格式，具有特定的类型和结构。

- **你项目中的例子**：`geometry_msgs/msg/Twist`（包含线速度和角速度）

### 2.4 服务（Service）

**服务**是节点间**同步**、**双向**的通信机制，采用**客户端/服务器**模式（请求-应答）。

- **你项目中的例子**：例如`/spawn`（生成新乌龟）或清空轨迹的服务

### 2.5 动作（Action）

**动作**用于**长时间**执行的任务。它采用客户端-服务器模型，一个“动作客户端”节点向一个“动作服务器”节点发送目标，
服务器节点确认目标并返回一系列**反馈**和**结果**流。动作提供了“请求-反馈-结果”机制，且可被取消。

- **你项目中的例子**：导航到目标点（过程中持续反馈距离进度）

### 2.6 功能包（Package）

**功能包**是ROS 2中代码的最小组织单元，包含源码、配置文件、启动文件等。

- **你项目中的例子**：你`git clone`下来的`diff_drive_robot`文件夹就是一个功能包

### 2.7 工作区（Workspace）

**工作区**是一个文件夹目录（通常名为`ros2_ws`或`your_ws`），包含`src`、`build`、`install`、`log`子目录，
是开发代码的总基地。

- **你项目中的例子**：你的`~/Documents/Diff_drive_robot_ws/`

### 2.8 启动文件（Launch File）

**启动文件**用于一次性启动多个节点和配置的脚本文件（在ROS 2中特指Python脚本）。

- **你项目中的例子**：`robot.launch.py`一次性启动了Gazebo、桥接、状态发布等多个节点

### 2.9 参数（Parameter）

**参数**是节点运行时的配置值（如PID控制系数、车轮半径）。

- **你项目中的例子**：位于`config/`目录下的`.yaml`文件中

## 三、一个基本ROS 2项目的目录组织方式

一个规范的ROS 2项目通常分为**工作区（外层）** 和**功能包（内层）**。

### 3.1 工作区根目录

```text
Diff_drive_robot_ws/
├── src/           # 源代码目录（手动创建，存放所有功能包）
├── build/         # 编译中间文件（由 colcon build 自动生成）
├── install/       # 编译后的可执行文件和库（由 colcon build 生成，source 这里）
└── log/           # 编译和运行的日志（由 colcon build 生成）
```

### 3.2 功能包内部

```text
diff_drive_robot/                   # 功能包根目录
├── CMakeLists.txt                 # (C++包) 编译规则文件
├── package.xml                    # 包的"身份证"：声明包名、版本、作者、依赖
├── launch/                        # 存放所有 .launch.py 启动脚本
│   ├── robot.launch.py
│   └── mapping.launch.py
├── config/                        # 存放 .yaml 参数配置文件
│   ├── ekf.yaml
│   └── slam_toolbox_mapping.yaml
├── urdf/                          # 存放机器人模型描述文件 (.xacro 或 .urdf)
│   └── diff_drive_robot.urdf.xacro
├── src/                           # 存放 Python 或 C++ 源代码
│   └── ...                        # (这里通常放自定义的Python节点)
├── msg/                           # (可选) 存放自定义消息类型 .msg
└── srv/                           # (可选) 存放自定义服务类型 .srv
```

## 四、需要编写什么语言的脚本？这些脚本做什么？

### 4.1 编程语言：C++ 与 Python

- **C++**：编译型语言，**运行效率高**。用于运动控制、图像处理、导航规划等对实时性要求高的核心算法
- **Python**：解释型语言，**开发速度快**。用于编写启动文件(`.launch.py`)、快速原型验证、简单逻辑节点

### 4.2 四种核心脚本文件

| 文件类型     | 语言/格式          | 核心作用                                                                                                                      | 具体例子                                                              |
| :----------- | :----------------- | :---------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------- |
| **节点源码** | `.cpp` 或 `.py`    | **实现业务逻辑**。这是ROS项目的"灵魂"。比如：发布者（读取雷达数据）、订阅者（控制电机）、服务端（处理路径请求）               | 你写的`my_controller.py`接收`/cmd_vel`并计算电机转速                  |
| **启动文件** | `.py`（ROS 2特有） | **"一键启动"脚本**。负责启动多个节点、设置参数、重映射话题。**注意**：ROS 2已废弃`.launch`（XML）格式，**必须使用Python脚本** | 你的`robot.launch.py`里包含了启动Gazebo、桥接器、状态发布器的代码逻辑 |
| **模型描述** | `.xacro`（XML宏）  | **描述机器人物理结构**。定义连杆长度、关节类型、颜色、碰撞体积。Gazebo利用它渲染机器人                                        | 你项目中的`diff_drive_robot.urdf.xacro`                               |
| **参数配置** | `.yaml`            | **静态参数存储**。将节点运行时需要调整的数值（如PID增益、滤波器系数）抽取出来，方便修改而无需重新编译代码                     | `config/ekf.yaml`里写满了卡尔曼滤波的噪声协方差矩阵                   |
